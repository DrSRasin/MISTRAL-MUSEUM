## Provenance

While preparing a **medRxiv-primary** scientific writing pocket reference, the operator wandered into the **Bench>Press / HighWire** submission help layers — the same family of systems that still power “create account / remember email / Log in with ORCID” walls.

The **policy** for what may be posted is modern (openRxiv-era FAQ).

This exhibit preserves the **pearls** for culture and calibration — and labels them as fossils so no future AI treats Cookie Cutter as a real diagnostic path.

## Specimens (primary quotes)

### Case 1 — Save is not a thing

> How do I save a PDF to my computer?  
> The Adobe Acrobat Reader allows you to view and print articles but does not allow you to save an article to your own computer.

**2026 translation:** The browser already has the bytes. Use Save As / Download. Modern Acrobat/Preview can save. The tip describes a **Reader vs full Acrobat** licensing myth from another century.

---

### Case 2 — Cookie Cutter & WebFree (Macintosh)

> It may be that you are using a program on your computer that automatically deletes cookies. Two such programs for the Macintosh are “Cookie Cutter” and “WebFree.” You will need to create an exception to use the online submission system.

**2026 translation:** Allow cookies for `submit.medrxiv.org`. Do not install a 1999 cookie utility. Private browsing and enterprise MDM are the modern villains.

**Operator parallel:** *“Why don’t you use normal Windows XP?”* — Chechnya, ~2010, after a Mac died; tech found by the guards. Same theology: there is one **normal** stack.

---

### Case 3 — Clock heresy

> The date is set incorrectly on your computer. This confuses our cookies (they have expiration dates), so please check to see that your date is set accurately.

**2026 translation:** System clock skew can still break TLS/cookies; the *voice* of the advice remains delightfully parental.

---

### Case 4 — Upgrade your browser (from the Bronze Age)

> Your browser is an old version that does not support cookies. You will need to upgrade it.

**2026 translation:** Use a current browser. IE is not a plan.

---

### Case 5 — The proxy ate my session

> You are accessing the system via a “proxy server” that is deleting cookies automatically. You should contact your network administrator to determine whether your institution’s proxy server is the source of the trouble.

**2026 translation:** Corporate SSL inspection / privacy proxies still exist. Call IT only after you’ve tried a non-private window.

---

### Case 6 — Enabling JavaScript (Internet Explorer, Windows)

> Enabling Javascript  
> Microsoft Internet Explorer (Windows)  
> Select Internet Options from the Tools menu.  
> Click the Security tab.  
> Click Custom Level in Security Level for this Zone.

**2026 translation:** Turn JS on in a living browser. There is no Tools → Internet Options pilgrimage.

---

### Case 7 — LaserWriter 8.4 (the downgrade gospel)

> Try printing to a newer printer. (NOTE for Macintosh users: A number of users have reported problems printing PDFs with the LaserWriter Driver version 8.4. We suggest using an earlier version.)

**2026 translation:** Open PDF in Preview/Chrome and print. **Do not** hunt LaserWriter 8.3 on a floppy.

**Comedy rank:** ★★★★★ — the system recommends *downgrading* the printer stack.

---

### Case 8 — Word is a bad figure aquarium

> We occasionally see problems with images that are created in a graphics application and then embedded in a Microsoft Word document. If this happens, you might try saving the figures to a TIFF or Encapsulated Postscript (EPS) file instead of using Word.

**2026 translation:** Still **good advice**. Separate figure files (TIFF/PNG/PDF). EPS is the period costume; the principle stands.

---

### Case 9 — NORMAL WINDOWS (Mac Word must repent)

> If you wrote your manuscript on a Macintosh using Microsoft Word or WordPerfect, you might try opening your file(s) using the Windows version of the same program. Our conversion system runs on Windows, and we have occasionally seen Macintosh files that appeared differently when opened in Windows. If this happens with your manuscript, you may need to edit and save your file in Windows rather than Macintosh.

**2026 translation:** Cross-platform Word still has ghosts. Better: ship a **PDF you already verified** so *you* own the rendering.  
**Cultural translation:** *Why don’t you use normal Windows XP?*

---

### Case 10 — Unsupported formats (CorelDRAW forever)

> Formats not supported include the following: Bitmap (.bmp), PICT (.pict), Excel (.xls), Photoshop (.psd), Canvas (.cnv), CorelDRAW (.cdr)

**2026 translation:** Export to PDF/TIFF/JPEG before you dream of the converter.  

**Curator note:** `.cdr` is not just a format — it is a **civilization**. One licensed seat, one person who “knew Corel,” a folder nobody can open a decade later. HighWire refused to run Corel on the farm. Correct. Sacred.

---

### Case 11 — The FAQ that is a login form

URL pattern: `https://submit.medrxiv.org/submission/faq?faqarea=submission`

**Observed (unauthenticated):** Create account · forgotten password · Security FAQ · email/password · ORCID · “Welcome to the medRxiv manuscript processing system.”

**Not observed:** Article-type policy, ethics, trial registration.

**2026 translation:** Policy = **www.medrxiv.org/about/FAQ** and **submit-a-manuscript**. The submit host FAQ is often a **door**, not a document.

---



### Case 12 — The eternal page (caching is your fault)

> I keep seeing the same page and can't get past it. What's going on?  
> The most likely source of this caching problem is your own computer.

**2026 translation:** Sometimes browser cache *is* sticky. More often the form lost the session cookie (see Cookie Cutter), the wizard crashed mid-step, or HighWire’s multi-page state machine is looping.  
**Institutional theology:** when navigation fails, **blame the visitor’s machine first**.

**Comedy rank:** ★★★★☆ — pairs with “wrong system date confuses cookies.”

**Operator note (2026-08-11):** These FAQ strata will serve for a long time. Accession permanent.




### Case 13 — One file at a time (radical permission)

> Can I upload one file at a time?  
> Yes, you can.

**2026 translation:** Still true. Still the shortest honest answer in the entire help corpus.

**Comedy rank:** ★★☆☆☆ — not funny because absurd; funny because after Cookie Cutter, LaserWriter 8.4, and “your computer is caching,” the system finally answers a normal question with **three words of yes**.

**Curator note:** Proof that HighWire *can* write plain English. It simply chooses not to, most of the time.
